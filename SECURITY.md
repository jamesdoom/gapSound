# Security policy and threat model

This development version is for one trusted user on localhost only. Report issues privately to the repository owner; no dedicated disclosure address has been configured. Do not submit sensitive data in public issues.

## Assets and trust boundaries

Assets: research notes, learning records, saved intelligence and local database. Boundaries: untrusted browser requests → API; public feed content → parser/database; database → React; workstation → external publishers. There are no API keys or AI services in this release.

| Threat                                  | Defense                                                                                                                                            | Residual risk                                                                                                              |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| CSRF and local DNS rebinding            | Exact Host and Origin checks on API, Fetch Metadata checks, JSON writes require Origin; localhost-only scripts                                     | No protection against malicious same-origin scripts, browser extensions or local processes                                 |
| Stored XSS and malicious feed markup    | React escaping, plain-text feed metadata, unsafe URL rejection, no raw HTML or remote media                                                        | Notebook uses restricted Markdown with inert HTML/no media; unsafe-inline remains necessary for initial Next bootstrap CSP |
| SSRF and unsafe redirects               | Fixed HTTPS source allowlist, public DNS address validation and pinning, redirect rejection, 15s total timeout, 10MiB response cap                 | Validated DNS answers are pinned into the HTTPS socket; trusted source content and workstation compromise remain risks     |
| Injection and malformed inputs          | Drizzle parameterization, Zod boundaries, XML entity/DTD rejection, bounded item count                                                             | Parser/library defects remain possible; no independent security audit                                                      |
| Resource exhaustion and source overload | 32KiB input limit, bounded query results, one refresh at a time, persisted exponential backoff and Retry-After delays, sequential network requests | Local write rate limits and stricter body streaming deadlines remain pending                                               |
| Accidental exposure and secret leakage  | No default external bind, ignored env/database, no paid AI calls, fixed error messages, no input logging                                           | Files unencrypted at rest; workstation user can read data                                                                  |

Security headers include nosniff, DENY framing, no-referrer, restrictive permissions and CSP with no external scripts, images or connections. CSP allows inline scripts/styles for Next; nonce-based policy is pending. Do not weaken boundaries to make tests pass.

Feed URLs are configured in code, never supplied by user input. Article links are not fetched by the server. Publishers receive refresh requests; users can choose whether to open original articles in their browser. Notes are never sent to any AI provider.

Tests cover local origin/host rules, oversized JSON, unsafe link schemes, malicious XML declarations, normalization and database constraints. Browser tests additionally verify literal malicious note markup and API cross-origin/rebinding rejection. Passing tests is not a security certification. Dependency auditing is part of CI; redacted secret scanning and synthetic backup/restore validation are now implemented; full native accessibility signoff and publisher reuse/notice gates remain outstanding. Public hosting needs reviewed authentication, authorization, sessions, HTTPS and deployment controls before implementation.

Local access defaults to port 3000; the isolated browser test server uses port 3100 via a validated GAPSOUND_PORT setting. Both configurations accept only exact localhost/127.0.0.1 hosts and matching origins. Failed source attempts persist their next eligible time, so browser refreshes and app restarts do not bypass rate limits. No in-request retry loops are used. Multi-process coordination and randomized jitter remain unimplemented.

Retention is a manual, confirmed mutation behind the local same-origin boundary. Server-side predicates protect recent and bookmarked articles even when confirmation payloads are tampered with. Only supplied preview IDs can be deleted in batches of at most 400, and preview cutoffs expire after 15 minutes. There is no automatic personal-data deletion. This is not secure erasure: SQLite free pages and backups may retain removed content. Preview/confirmation does not defend against malware or compromised same-origin scripts.

Watchlist mutations validate names, UUIDs and bounded literal terms behind the local Host/Origin boundary. Edits are transactional, lists are capped at 50 and terms at 10 per list; arbitrary regex and SQL fragments are never executed. Removal requires explicit confirmation and excludes article data. CVE links are constructed only from recognized identifier characters, and mentions are not presented as verified records or exploitation. KEV membership refers only to the stored local catalog; stale catalog and source misstatements remain risks. No AI or new external requests are involved.

Feed normalization now rejects unsupported documents and nonempty feeds with no usable entries, so an access-denied HTML page cannot advance successful-refresh freshness. XML size and nesting are bounded; DTD/custom entities remain blocked. Known HTML entities are decoded to plain text, with script/style/template blocks removed and React still escaping output. Publication dates require timezone evidence and calendar validation. No feed-provided URLs or embedded content are fetched. Text extraction is not a general HTML sanitizer.

Daily briefings are local snapshots, not live incident assessments. Generation validates the current local day and IANA time zone, bounds candidate/result sizes, validates stored JSON/references on write/read and makes no external calls. GET has no mutation side effects; generation/archiving require the same local-origin protections as other writes. Regeneration and prior-version archiving are one transaction, with rollback coverage. Objectives may contain personal text and snapshots remain retained after article cleanup; no automatic erasure or encryption is provided. Stored references are rendered as escaped text with safe links.

Scheduled reviews use bounded topic text, validated calendar dates/UUIDs, paginated reads and a 10,000-record cap. All mutations retain the local same-origin boundary. Completed records cannot be silently reopened/rescheduled; a new record preserves previous completion history. Review topics are private data also captured in retained briefing snapshots. Scheduling performs no network requests, notifications or executable actions.

Training completion/recovery requires the current active session UUID and validates that the UTC end lies between its start and server time. Stale controls cannot finish a replacement session. Reads do not create sessions or reset objectives. Recovery is a same-origin bounded mutation, with no external execution or network activity. A user-selected local end time is converted by the browser; clock/time-zone changes and DST ambiguity require the user to verify the displayed session history.

Notebook edits use UUID/revision checks to prevent silent stale overwrites, with atomic note/tag updates. Markdown is rendered as React elements with no raw HTML plugins, disabled images and validated HTTPS links only; no note URL is fetched by the server. Pages/exports are bounded, and all-note downloads stop at 10,000 notes or 10 MiB with no partial download. Exports retain original source and private text. Tag backfill preserves legacy note content. No notebook deletion or automatic erasure was introduced.

CVE research accepts validated identifiers only, constructing one fixed CVE Program HTTPS endpoint behind the existing DNS-pinned, public-address-only, no-redirect transport (15 seconds/2 MiB). GET/save/filter make no external calls; lookup/refresh is an explicit same-origin POST. Persisted leases/cooldowns and bounded projections protect provider/local resources. Failure preserves last-good metadata and saved markers. Raw source text is escaped, references are safe HTTPS links and are not fetched by the server. An unavailable public record or missing KEV match is never treated as evidence of safety or nonexistence. No NVD/EPSS/AI integration or user exposure inference was introduced.

Publisher-policy review is recorded in docs/SOURCE_POLICIES.md. The server enforces a 60-minute SANS floor on legacy/new attempts, success and failure; other feed defaults remain 15 minutes. Longer Retry-After/backoff wins. Robots is not treated as a reuse license, and fixed feed paths do not permit arbitrary crawling. Review does not clear public redistribution or resolve missing publisher permissions/CVE license packaging. No stored articles, bookmarks or briefing history were removed.

Persistence/accessibility verification uses isolated temporary databases and loopback test servers (3100 regular suite, 3101 process-restart fixture, 3102 manual kit). Restart tests terminate only child processes they created, after completed same-origin writes; no production control endpoint or trust-boundary bypass was added. The manual kit holds publisher requests behind temporary persisted cooldowns and does not modify the user database. Forced-colors styles use system palette values and retain normal browser accessibility handling. Native desktop checks remain unsigned after Computer Use stopped on an unverified-browser-URL safety condition; no alternative desktop-input path was attempted.

Backup/restore are terminal-only operations, never web endpoints. New directories are created exclusively and restore verifies a copied snapshot against its manifest plus SQLite integrity/foreign keys/migration history. Hashes detect accidental corruption, not a maliciously replaced bundle; only trusted backups should be restored with the corresponding app revision. Failed output remains for diagnosis and must not be used. Backups are private and unencrypted, with inherited Windows ACLs. The pinned Gitleaks scanner checks Git history and non-ignored source files with fully redacted output; ignored personal files and remote-only refs are outside scope. See docs/RELEASE_ACCEPTANCE.md.

Reusable objective plans use bounded same-origin JSON requests, at most 20 distinct 200-character titles and a bounded serialized plan. Revision checks prevent stale-tab overwrites; plan application validates the current local day/time zone, appends at most 100 daily objectives and commits copied tasks plus a unique daily marker atomically. Reads do not write. Existing tasks and briefing snapshots are preserved when plans change; plan titles remain private local study text and may be copied into briefings/backups. No external scheduling or execution is performed.
