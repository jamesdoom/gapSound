# Security policy and threat model

This development version is for one trusted user on localhost only. Report issues privately to the repository owner; no dedicated disclosure address has been configured. Do not submit sensitive data in public issues.

## Assets and trust boundaries

Assets: research notes, learning records, saved intelligence and local database. Boundaries: untrusted browser requests → API; public feed content → parser/database; database → React; workstation → external publishers. There are no API keys or AI services in this release.

| Threat                                  | Defense                                                                                                                                            | Residual risk                                                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| CSRF and local DNS rebinding            | Exact Host and Origin checks on API, Fetch Metadata checks, JSON writes require Origin; localhost-only scripts                                     | No protection against malicious same-origin scripts, browser extensions or local processes                             |
| Stored XSS and malicious feed markup    | React escaping, plain-text feed metadata, unsafe URL rejection, no raw HTML or remote media                                                        | No rich Markdown yet; unsafe-inline remains necessary for initial Next bootstrap CSP                                   |
| SSRF and unsafe redirects               | Fixed HTTPS source allowlist, public DNS address validation and pinning, redirect rejection, 15s total timeout, 10MiB response cap                 | Validated DNS answers are pinned into the HTTPS socket; trusted source content and workstation compromise remain risks |
| Injection and malformed inputs          | Drizzle parameterization, Zod boundaries, XML entity/DTD rejection, bounded item count                                                             | Parser/library defects remain possible; no independent security audit                                                  |
| Resource exhaustion and source overload | 32KiB input limit, bounded query results, one refresh at a time, persisted exponential backoff and Retry-After delays, sequential network requests | Local write rate limits and stricter body streaming deadlines remain pending                                           |
| Accidental exposure and secret leakage  | No default external bind, ignored env/database, no paid AI calls, fixed error messages, no input logging                                           | Files unencrypted at rest; workstation user can read data                                                              |

Security headers include nosniff, DENY framing, no-referrer, restrictive permissions and CSP with no external scripts, images or connections. CSP allows inline scripts/styles for Next; nonce-based policy is pending. Do not weaken boundaries to make tests pass.

Feed URLs are configured in code, never supplied by user input. Article links are not fetched by the server. Publishers receive refresh requests; users can choose whether to open original articles in their browser. Notes are never sent to any AI provider.

Tests cover local origin/host rules, oversized JSON, unsafe link schemes, malicious XML declarations, normalization and database constraints. Browser tests additionally verify literal malicious note markup and API cross-origin/rebinding rejection. Passing tests is not a security certification. Dependency auditing is part of CI; dedicated secret scanning, full accessibility review, expanded transport failure tests and backup/restore validation are outstanding. Public hosting needs reviewed authentication, authorization, sessions, HTTPS and deployment controls before implementation.

Local access defaults to port 3000; the isolated browser test server uses port 3100 via a validated GAPSOUND_PORT setting. Both configurations accept only exact localhost/127.0.0.1 hosts and matching origins. Failed source attempts persist their next eligible time, so browser refreshes and app restarts do not bypass rate limits. No in-request retry loops are used. Multi-process coordination and randomized jitter remain unimplemented.

Retention is a manual, confirmed mutation behind the local same-origin boundary. Server-side predicates protect recent and bookmarked articles even when confirmation payloads are tampered with. Only supplied preview IDs can be deleted in batches of at most 400, and preview cutoffs expire after 15 minutes. There is no automatic personal-data deletion. This is not secure erasure: SQLite free pages and backups may retain removed content. Preview/confirmation does not defend against malware or compromised same-origin scripts.

Watchlist mutations validate names, UUIDs and bounded literal terms behind the local Host/Origin boundary. Edits are transactional, lists are capped at 50 and terms at 10 per list; arbitrary regex and SQL fragments are never executed. Removal requires explicit confirmation and excludes article data. CVE links are constructed only from recognized identifier characters, and mentions are not presented as verified records or exploitation. KEV membership refers only to the stored local catalog; stale catalog and source misstatements remain risks. No AI or new external requests are involved.

Feed normalization now rejects unsupported documents and nonempty feeds with no usable entries, so an access-denied HTML page cannot advance successful-refresh freshness. XML size and nesting are bounded; DTD/custom entities remain blocked. Known HTML entities are decoded to plain text, with script/style/template blocks removed and React still escaping output. Publication dates require timezone evidence and calendar validation. No feed-provided URLs or embedded content are fetched. Text extraction is not a general HTML sanitizer.
