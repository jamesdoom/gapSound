# Publisher attribution and notice packaging

Reviewed November 25, 2026. This update implements notice retention for the local reader; it does not authorize public hosting, commercial use or publisher republication.

## Verified source material

The CVE Program's [current terms](https://www.cve.org/Legal/TermsOfUse) require its copyright designation and license to accompany copies. The official [CVE website terms source](https://github.com/CVEProject/cve-website/blob/9d1ab813f5274ffc136e0bf55e74f9cf1b552da9/src/views/Legal/TermsOfUse.vue) supplies the full Submissions, CVE Usage and Disclaimers text. Its [footer source](https://github.com/CVEProject/cve-website/blob/9d1ab813f5274ffc136e0bf55e74f9cf1b552da9/src/components/FooterModule.vue) supplies the copyright designation, with its computed year resolved to 2026 for this dated review, and trademark wording. The served public website asset was also checked against these terms/footer strings. No CVE software-repository license was substituted for the dataset's terms.

The [official CISA KEV license](https://github.com/cisagov/kev-data/blob/develop/LICENSE) supplies its full CC0 text and its separate third-party-link, logo and endorsement limitations. The [SANS static-feed guidance](https://isc.sans.edu/feeds_doc.html), [Krebs homepage](https://krebsonsecurity.com/) and [BleepingComputer terms](https://www.bleepingcomputer.com/terms-of-use/) were rechecked. They support the dated source/attribution decisions in SOURCE_POLICIES.md, not a claim of blanket permission for diary/article republication. No publisher was contacted.

The reviewed bundle is `src/lib/publisher-notices.json`. CVE legal text is preserved in full with presentation whitespace normalized and the trademark rendered as plain Unicode text. Its UTF-8 text SHA-256 is `bb006467c4cc4346e9d6da5b45717eb0726e5d5f8466c56b9eba9adc1f7181e5`. The trimmed CISA license text SHA-256 is `8dfcf2d0cba33bede386eb470daf2ac08caf6540fc2516baab10dd546f90938a`. Tests compare these reviewed fingerprints and verify that the SQL migration stores the exact bundle. Changes require a new review and migration; do not silently edit an already applied migration or rewrite historical snapshots.

## Where notices travel

| Surface             | Behavior                                                                                                                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local database      | Migration 0010 adds the complete bundle in `dataset_notices` and nullable article notice metadata. Existing article content, bookmarks/read state, notes, CVE snapshots and briefing JSON are preserved.                                                                              |
| New CVE snapshots   | Include the complete CVE copyright/license bundle inside the bounded normalized projection. Metadata trimming never removes the notice bundle.                                                                                                                                        |
| Feed articles       | Retain recognized channel/item `copyright`, `rights` (including namespace-stripped Dublin Core fields) and text `license` fields as plain text. Article cards display these and configured publisher attribution.                                                                     |
| Feed refresh        | Missing notice fields preserve the last stored notice for that article; a newly supplied notice replaces the current notice. Bookmarks/read state remain intact.                                                                                                                      |
| New saved briefings | Include the reviewed bundle and each selected article's captured publisher notice. Archived versions retain their original captured notice text.                                                                                                                                      |
| Legacy snapshots    | Remain readable without mutation. The CVE API supplies supplemental notices; legacy briefing views explicitly label supplemental current notices separately from saved snapshot content. Previously omitted feed notices cannot be reconstructed from old snapshots.                  |
| API responses       | Workspace, vulnerability and briefing reads include a standalone notice bundle alongside data, including legacy data. Local Host/Origin/Fetch Metadata checks remain enforced.                                                                                                        |
| Notice download     | Settings and vulnerability/briefing views offer a local JSON notice download at `/api/notices`. It is static packaged content, requires local access and makes no publisher request.                                                                                                  |
| SQLite backups      | New bundles contain `publisher-notices.json`, plus its SHA-256 in the manifest. Notices come from the snapshot's stored bundle when present; a pre-0010 source receives supplemental packaged notices without altering that source database. Restore verifies and copies the sidecar. |

Old backup manifests without the optional notice checksum remain readable. They are not retroactively upgraded or represented as verified notice sidecars. Corresponding repository notice files can accompany such legacy copies; follow the documented application-version/migration requirements before using restored data. A checksum detects accidental changes, not a maliciously replaced manifest and database.

Notebook exports contain user-authored or manually pasted text; the app does not automatically import publisher content into notes or infer rights for arbitrary pasted material. Users must retain applicable third-party notices with such text. This change adds no publisher-data republication/export feature beyond the existing local API and backup workflows. Dataset notices do not constitute a license for GapSound source code or clear software-dependency distribution obligations.

## Bounds, safety and remaining gates

Recognized feed notices are deduplicated and limited to 5,000 characters total per article. Oversized or unsupported structured notice fields fail that source import rather than silently clipping a notice. Existing source rollback/backoff behavior applies. Other feed/title/summary caps and fixed-source DNS-pinned transport remain unchanged. The app does not fetch notice URLs, article bodies, logos or linked license pages at runtime. Notices render as escaped React text with wrapping; stored notice links pass the same safe HTTPS check as other references.

This retention covers recognized metadata fields, not every possible proprietary notice embedded in publisher prose, media or full article bodies. Additional provider fields and changed policies require review. Original links and attribution are retained, but attribution is not permission. Public/commercial use of SANS diary prose, BleepingComputer material or publisher-derived briefings, and broader Krebs reuse, remain unresolved. Do not declare GS-003 or Phase 1 accepted on the basis of this packaging update alone.

Verification uses synthetic feeds/data, exact notice fingerprints, database/migration rollback checks, backup/restore corruption checks, and browser checks of local downloads, visible attribution, safe access, mobile wrapping and accessibility. Native assistive-technology signoff remains separate.
